# 社团管理系统 · 前端设计方向

三个可选的设计方向，功能完全相同，差别在语气、密度与形制。用于选定视觉语言，之后再用
Vue 3 + Element Plus 把选定方向落地。

## 怎么打开

直接双击 `index.html`，或用浏览器打开：

```
design/index.html
```

不需要启动任何服务，也不需要联网。GSAP 已放在 `vendor/` 本地，照片也在 `img/` 本地。

每个方向页顶部有一条深色的**原型切换条**（不属于设计本身），可以在三个界面之间跳转。
也可以直接用 hash 打开某个界面，方便分享链接：

| 链接 | 界面 |
|---|---|
| `direction-a.html#login` | 方向 A 登录页 |
| `direction-a.html#dashboard` | 方向 A 概览 |
| `direction-a.html#members` | 方向 A 成员管理 |

把 `direction-a` 换成 `direction-b` 或 `direction-c` 即可。

## 先说明一件事：技能适用范围

你指定使用 `design-taste-frontend` 技能，这个技能的规则我逐条应用了（对比度、禁止 em dash、
不用 Inter 作默认、禁止三等分卡片、禁止装饰性状态点、眉标数量上限、CTA 不重复等）。

但它在第 13 节明确写了**不适用于仪表盘与后台管理界面**，原文是：

> This skill is NOT for: Dashboards / dense product UI / admin panels (use Fluent, Carbon,
> Atlassian, or Polaris), Data tables, Multi-step forms / wizards.

同一节也要求遇到这种情况时**明确说出来并指向正确的工具**，而不是硬套。所以我的处理是：

1. **仪表盘、成员表、表单这些界面，按它的建议改用真实设计系统**。我们的技术栈是
   Vue 3，对应的真实设计系统就是 **Element Plus**（不是手写一套 CSS 冒充设计系统）。
2. **仍然严格套用它的通用规则**：可访问性对比度、动效必须有动机、禁止 AI 套路配色与排版、
   完整的加载与空状态、形状与色彩的全局一致性锁定。这些规则对所有界面都成立。
3. **它真正适用的部分是登录页与社团对外展示页**，这两块按它的完整要求做（真实照片、
   英雄区文案纪律、CTA 唯一性、正文长度上限等）。

所以下面三个方向可以理解为：**用它的规则约束出来的三套视觉语言，承载在 Element Plus 之上**。

## 设计读与三个刻度

技能要求先声明设计读（Design Read），再据此设定三个刻度。整体设计读为：

> 面向社团干部与普通成员的内部管理台，外加一个公开的社团主页；
> 语气偏克制技术，视觉语言由 Element Plus 定制主题承载，而不是沿用它的默认外观。

三个刻度分别控制版面变化度（VARIANCE）、动效强度（MOTION）、信息密度（DENSITY）。
三个方向就是三组不同的取值：

| 方向 | VARIANCE | MOTION | DENSITY | 主题 |
|---|---|---|---|---|
| A · 静默墨蓝 | 4 | 3 | 6 | 浅色锁定 |
| B · 石墨终端 | 6 | 6 | 7 | 深色锁定 |
| C · 留白方格 | 8 | 5 | 3 | 浅色锁定 |

---

## 三个方向

### A · 静默墨蓝（Calm Cobalt）

常规管理控制台。左侧栏 232px，指标行加双栏面板，成员用表格。语气克制、可信、可预期。

- 强调色：钴蓝 `#3553c6`，饱和度 57%，无霓虹发光
- 形制：容器 10px / 控件 8px / 标签 6px，全站无胶囊
- 动效最克制：只在首次进入时播一次淡入与数字增长，不重播
- **适合**：评委偏好稳妥专业、你想少踩坑。三选一里最不容易出错。

### B · 石墨终端（Graphite Terminal）

技术类社团自己的管理台。等宽数字、细线分隔、信息密度最高，气质接近开发工具。

- 强调色：祖母绿 `#2fa37a`，饱和度 52%
- 配色：石墨近黑 `#0e1012`，刻意不用纯黑
- 形制：容器 6px / 控件 6px / 标签 4px，直角感更强
- 动效最明显：多一条随滚动绘制的经费趋势线；唯一的循环动效是"报名中"那个实时指示点
- 深色上的主按钮用**近黑字**：白字在绿底上只有 3.2:1，不达标
- **适合**：想靠观感抓人。深色界面在答辩投屏时最抓眼。

### C · 留白方格（Quiet Bento）

给不常来后台的普通成员用。顶部导航取代侧栏，六列 bento 卡片网格取代密集表格，留白最大。

- 强调色：赭红 `#b34a26`，饱和度 65%
- 形制：容器 16px，按钮、标签、头像一律胶囊，与 A 的圆润和 B 的直角都不同
- 结构差异最大：无侧栏，导航单行；版面变化度 8，格子大小刻意不齐
- 动效适中：格子错峰浮现，悬停轻微抬起
- **适合**：想让系统看起来不像后台。移动端体验最好，但一屏能承载的模块数最少。

---

## 我的建议

**推荐 A。** 理由是它把风险降到最低：浅色配色的对比度容易达标，版面结构清晰好实现，
竞赛评委对它的接受度最高，而且它最省你的时间，可以把精力放到功能完整度上（那才是评分的大头）。

**如果你更想赢在观感，选 B。** 深色界面演示时的视觉冲击明显更强，也能呼应"计算机协会"
这个技术身份。代价是深色配色要逐项校对比度，比 A 多花时间。

**C 更适合作为"移动端"或"面向普通成员"的补充方案**，不建议作为管理后台的主方向，
因为一屏能承载的信息量最少，干部日常操作会多点几次。

> 也可以混合：主后台用 A，社团对外主页和移动端用 C 的形制。两者共享同一套 tokens，不冲突。

## 原型里能真实触发的状态

不是静态贴图。下面这些在每个方向里都能点：

- **登录校验**：留空提交显示行内错误，填任意内容即可进入后台
- **加载骨架屏**：进入成员管理时先出现与最终表格同形的占位块，不产生布局跳动
- **搜索与筛选**：按姓名、学号、手机号搜索，叠加部门与状态筛选
- **空状态**：筛不出结果时出现空状态面板，附清空条件按钮
- **未完成模块占位**：点其他模块会看到明确的"尚未绘制"占位，不假装有内容
- **降低动态偏好**：系统开启"减少动态效果"后，所有动画折叠为静态，页面照常可用

## 文件结构

```
design/
  index.html              方向对比总览（入口）
  direction-a.html        方向 A 完整原型
  direction-b.html        方向 B 完整原型
  direction-c.html        方向 C 完整原型
  css/
    base.css              重置 + 原子组件 + 原型外壳（三方共用）
    console.css           管理台通用结构层，只消费 tokens（三方共用）
    a-calm.css            方向 A 的 tokens
    b-graphite.css        方向 B 的 tokens 与形制覆盖
    c-bento.css           方向 C 的 tokens 与特有结构
    index.css             对比总览页
  js/
    motion.js             动效原语：数字增长、入场、滚动揭示、线条绘制
    shell.js              管理台外壳逻辑：界面切换、筛选、加载态、登录校验
    a.js / b.js / c.js    各方向的动效配置
  vendor/
    gsap.min.js           GSAP 3.13（本地，不依赖 CDN）
    ScrollTrigger.min.js
  img/
    panel-calm.jpg        方向 A 登录页照片（占位）
    panel-graphite.jpg    方向 B 登录页照片（占位）
    panel-quiet.jpg       方向 C 登录页与 bento 照片（占位）
  shots/                  对比页用的界面截图
```

**架构说明**：`console.css` 是三个方向共用的结构层，只使用 CSS 变量，不定义任何具体颜色；
每个方向的样式文件只负责提供 tokens。所以换方向等于换一组变量，结构代码不动。
这套变量命名会原样映射到 Element Plus 的主题覆盖上。

## 需要你替换或注意的地方

1. **登录页照片必须换掉。** 目前是公共图库的抽象照片，只用来验证版面。请换成社团自己的
   活动照或校园照，替换 `img/` 下那三个文件即可，保持竖向比例效果最好。
2. **活动列表刻意没有放封面图。** 因为图库照片的题材（海滩、街景）和活动对不上，
   放上去会显得假。接入社团真实照片后再补这一块。
3. **所有数据都是构造的演示数据。** 其中 82 名成员、3 场活动、¥1,260 余额来自你给的示例，
   其余数字按内部逻辑配平：余额 = 期初结余 ¥1,860 + 收入 ¥4,400 - 支出 ¥5,000 = ¥1,260，
   部门人数 34 + 19 + 15 + 14 = 82，都能对上。
4. **这是设计原型，不是最终代码。** 纯 HTML 与 CSS 手写，没有引入 Vue 或 Element Plus，
   目的是先把视觉语言定下来，避免在业务代码里反复改颜色。
5. **图标用了 Tabler Icons（MIT 协议）**，已内联进 HTML，没有手画 SVG。

## 选定方向之后

我会按这个顺序推进：

1. **把 tokens 映射到 Element Plus 主题**。这里定义的 canvas / surface / border / text /
   accent / radius 会覆盖 Element Plus 的 CSS 变量，业务代码不出现任何颜色字面值。
2. **搭建 Vue 3 + Vite + NestJS 脚手架**，按之前定好的分层建目录。
3. **写 Prisma schema**（数据库设计已经定稿在 `docs/database-design.md`）。
4. **按方向补齐其余界面**：活动、报名签到、经费、审批、值班、通知、文件共享。

## 可访问性与动效说明

- **对比度**：三个方向的正文、控件文字、占位符、状态标签都按 WCAG AA（4.5:1）验算过，
  数值写在各自 tokens 文件的注释里。照片上的叠印文字另加压暗层保证达标。
- **动效都有动机**：数字增长是让读数像刚算出来，入场是引导阅读顺序，趋势线绘制是叙事，
  悬停抬起是反馈。没有一处是"因为能动画所以动画"。
- **不使用 `window` 滚动监听**。滚动揭示统一走 `ScrollTrigger.batch`，只动 `transform`
  与 `opacity`。
- **降低动态偏好**：全部包在 `prefers-reduced-motion` 判断里，触发时折叠为静态。
- **形状与色彩一致性**：每个方向锁定一套圆角规则与一个强调色，全站不混用。
